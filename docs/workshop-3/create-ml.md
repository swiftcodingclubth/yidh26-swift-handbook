# Create ML

**Create ML** คือ app บน Mac ที่ train machine learning model ได้โดยไม่ต้องเขียนโค้ด เราแค่เตรียมตัวอย่างข้อมูลที่ติดป้ายไว้ Create ML จะเรียนรู้รูปแบบจากตัวอย่างเหล่านั้น แล้วให้ไฟล์ model ที่นำไปใช้ใน app ได้ทันที ใช้ได้ทั้ง {{ mac.intel }} และ {{ mac.apple }}

เปิดได้จาก **Xcode › Open Developer Tool › Create ML**

## ทำงานอย่างไร { #how }

1. **เตรียมข้อมูลตัวอย่างที่ติดป้าย (label)** เช่น รูปแมวในโฟลเดอร์ `cat` รูปสุนัขในโฟลเดอร์ `dog` หรือประโยคที่บอกไว้ว่าเป็นอารมณ์อะไร
2. **Train** Create ML หารูปแบบที่แยกแต่ละป้ายออกจากกัน
3. **ทดสอบ** กับข้อมูลที่ model ไม่เคยเห็น เพื่อดูว่าใช้จริงได้ดีแค่ไหน
4. **Export** เป็นไฟล์ `.mlmodel` แล้วใช้ใน app ด้วย [Core ML](core-ml.md)

Template ส่วนใหญ่ไม่ได้เริ่มเรียนจากศูนย์ แต่ต่อยอดจาก model ที่ Apple train ไว้แล้วและมีอยู่ใน iOS (transfer learning) จึงใช้ข้อมูลไม่มาก train เสร็จในไม่กี่วินาทีถึงไม่กี่นาที และไฟล์ model มักมีขนาดเล็กมาก

## Create ML ทำ model แบบไหนได้บ้าง { #templates }

ตอนสร้าง project ใหม่ Create ML ให้เลือก **template** ตามชนิดข้อมูลที่มี

| ข้อมูล | Template | Model ตอบว่า | ข้อมูลที่ต้องเตรียม | ตัวอย่าง use case |
|---|---|---|---|---|
| รูปภาพ | **Image Classification** | รูปนี้คืออะไร | รูปแยกโฟลเดอร์ตามชื่อป้าย อย่างน้อยป้ายละ 10 รูป แนะนำ 50 รูปขึ้นไป | แยกขยะรีไซเคิล, บอกชนิดผลไม้, เช็กใบไม้เป็นโรค |
| รูปภาพ | **Object Detection** | ในรูปมีอะไรบ้าง อยู่ตรงไหน | รูป + ไฟล์ JSON ระบุกรอบ (ตำแหน่ง) ของวัตถุทุกชิ้น ต้องตีกรอบเองทีละรูป | นับสินค้าบนชั้น, หาป้ายจราจร |
| รูปภาพ | **Hand Pose Classification** | มือทำท่าอะไร | รูปมือแยกโฟลเดอร์ตามท่า | ภาษามือ, ท่ามือสั่ง app |
| วิดีโอ | **Action Classification** | คนในวิดีโอทำท่าอะไร | วิดีโอสั้นแยกโฟลเดอร์ตามท่า ถ่ายเห็นทั้งตัว | นับท่า jumping jack, เช็กท่าออกกำลังกาย |
| วิดีโอ | **Hand Action Classification** | มือเคลื่อนไหวแบบไหน | วิดีโอสั้นของมือแยกโฟลเดอร์ตามท่า | โบกมือ, ปัดมือสั่งเปลี่ยนหน้า |
| รูปภาพ / วิดีโอ | **Style Transfer** | แปลงรูปให้เป็นสไตล์ที่กำหนด | รูปสไตล์ 1 รูป + รูปหรือวิดีโอทั่วไปหลายรูป | filter กล้องแบบภาพวาดสีน้ำ |
| การเคลื่อนไหว | **Activity Classification** | ผู้ใช้ทำท่าอะไรกับเครื่อง | ไฟล์ CSV ค่า accelerometer และ gyroscope แยกโฟลเดอร์ตามท่า ต้องเก็บข้อมูลจากหลายคนเป็นเวลานาน | ท่ากายภาพบำบัด, แยกท่าตีเทนนิส |
| เสียง | **Sound Classification** | ได้ยินเสียงอะไร | ไฟล์เสียงสั้นแยกโฟลเดอร์ตามชื่อเสียง พร้อมโฟลเดอร์ `background` | จดจำเสียงไอ, เสียงเครื่องจักรผิดปกติ |
| ข้อความ | **Text Classification** :material-check-decagram:{ .pick title="ใช้ใน workshop นี้" } | ข้อความนี้เป็นประเภทอะไร | ไฟล์ CSV ที่มี column `text` และ `label` | อารมณ์จากข้อความ, แยกข้อความสแปม, จัดหมวดคำร้องเรียน |
| ข้อความ | **Word Tagging** | คำไหนในประโยคเป็นอะไร | ไฟล์ JSON ที่ติดป้ายให้ทุกคำ | ดึงชื่อสินค้าหรือชื่อสถานที่ออกจากข้อความ |
| ตาราง | **Tabular Classification** | แถวนี้อยู่กลุ่มไหน | ไฟล์ CSV หนึ่ง column เป็นคำตอบ ที่เหลือเป็นข้อมูลประกอบ | ทายว่าลูกค้าจะยกเลิกบริการไหม |
| ตาราง | **Tabular Regression** | ทายเป็นตัวเลข | ไฟล์ CSV หนึ่ง column เป็นตัวเลขที่ต้องการทาย | ประเมินราคาบ้าน, ทายเวลาเดินทาง |
| ตาราง | **Recommendation** | ผู้ใช้น่าจะชอบอะไร | ไฟล์ CSV ว่าผู้ใช้คนไหนชอบหรือให้คะแนนอะไร | แนะนำเมนูอาหาร, แนะนำหนังสือ |

นอกจากนี้ยังมี **Object Tracking** ที่ train จากไฟล์ 3D (USDZ) ของวัตถุ ใช้ติดตามวัตถุจริงบน Apple Vision Pro (visionOS) ไม่ได้ใช้บน iPad

!!! tip "เลือก template อย่างไร"
    เริ่มจากถามว่า **app มีข้อมูลแบบไหน** และ **อยากได้คำตอบแบบไหน** เช่น มีรูปถ่ายและอยากรู้ว่าเป็นอะไร ใช้ Image Classification ถ้าอยากรู้ตำแหน่งด้วย ใช้ Object Detection ก่อน train เอง ให้เช็กก่อนว่า framework ในตัวทำได้อยู่แล้วหรือยัง เช่น [Sound Analysis](sound.md) จดจำเสียงทั่วไปได้กว่า 300 แบบ และ model สำเร็จรูปจาก Apple ใน[หน้า Core ML](core-ml.md#pretrained) บอกได้ว่าในรูปมีอะไร โดยไม่ต้อง train

### ข้อมูลที่ดีเป็นแบบไหน

ความแม่นของ model ขึ้นกับข้อมูลมากกว่าการตั้งค่า ไม่ว่าจะใช้ template ไหน

| หลัก | ตัวอย่าง |
|---|---|
| **Label ต้องถูก** | รูปที่ใส่ผิดโฟลเดอร์ หรือประโยคที่ติดอารมณ์ผิด ทำให้ model เรียนรู้ผิด |
| **หลากหลายเหมือนการใช้งานจริง** | ถ่ายหลายพื้นหลัง หลายแสง หลายมุม ถ้าถ่ายบนพื้นหลังเดียวทุกรูป model จะจำพื้นหลังแทนสิ่งของ |
| **จำนวนใกล้เคียงกันทุกป้าย** | ถ้าป้ายหนึ่งมี 500 รูป อีกป้ายมี 20 รูป model จะเอนเอียงไปตอบป้ายที่มีเยอะ |
| **มีป้ายสำหรับ "อย่างอื่น"** | เช่น `other` หรือ `background` model จะได้ไม่ตอบป้ายใดป้ายหนึ่งเสมอ |
| **แยกข้อมูลทดสอบไว้** | ทดสอบกับข้อมูลที่ไม่ได้ใช้ train เท่านั้น จึงจะรู้ว่าใช้จริงได้ดีแค่ไหน |

## Workshop นี้: Text Classification { #workshop }

Workshop นี้ใช้ template **Text Classification** train model ที่อ่านข้อความภาษาอังกฤษแล้วบอกว่าเป็นอารมณ์อะไร จากนั้นนำไปใช้ในหน้า "วันนี้รู้สึกอย่างไร" ของ starter project ผ่าน [Core ML](core-ml.md#text-classifier)

## ข้อมูล { #data }

ใช้ข้อมูลในโฟลเดอร์ `EmotionData/` ของ [starter project](add-to-your-app.md#get-starter) ข้อความภาษาอังกฤษ 6 อารมณ์ มาจาก [Emotions dataset for NLP](https://www.kaggle.com/datasets/praveengovi/emotions-dataset-for-nlp) บน Kaggle

| ไฟล์ | จำนวน | ใช้ในช่อง |
|---|---|---|
| `emotion6_train.csv` | 18,000 ประโยค | **Training Data** |
| `emotion6_test.csv` | 2,000 ประโยค | **Testing Data** |
| `emotion6_mytest.csv` | 30 ประโยค | **+ New Test** (ประโยคที่แต่งขึ้นเอง ไม่อยู่ใน dataset) |

| label | จำนวนใน train |
|---|---|
| `joy` | 6,066 |
| `sadness` | 5,216 |
| `anger` | 2,434 |
| `fear` | 2,149 |
| `love` | 1,482 |
| `surprise` | 653 |

ไม่มี `neutral` model จะตอบอารมณ์ใดอารมณ์หนึ่งเสมอ แม้ข้อความจะไม่มีอารมณ์อะไร ตอนใช้ใน app จึงต้อง[ดูความมั่นใจประกอบ](core-ml.md#confidence)

### รูปแบบไฟล์

Text Classifier รับไฟล์ CSV ที่มี column ชื่อ **`text`** และ **`label`** เท่านั้น

```text
text,label
i didnt feel humiliated,sadness
i am feeling grouchy,anger
```

!!! warning "Error: missing required field label"
    Create ML เลือกชื่อ column เองไม่ได้ ถ้าไฟล์ใช้ชื่ออื่น เช่น `Emotion` หรือ `category` ต้องเปลี่ยนชื่อ column เป็น `label` ก่อน

## 1. สร้าง project

1. **File › New Project…** หรือกด **New Document** ที่หน้าแรก
2. เลือก **Text Classification** แล้วกด **Next**
3. ตั้งชื่อ เช่น `EmotionClassifier` ชื่อนี้จะเป็นชื่อ class ใน Xcode ด้วย

## 2. ใส่ข้อมูล

แท็บ **Settings**:

| ช่อง | ใส่อะไร |
|---|---|
| **Training Data** | ลาก `emotion6_train.csv` มาวาง |
| **Validation Data** | **Automatic** (Create ML แบ่งข้อมูลส่วนหนึ่งไว้ตรวจให้เอง) |
| **Testing Data** | ลาก `emotion6_test.csv` มาวาง |

ลากไฟล์แล้วควรเห็น 6 classes ถ้าเห็น error ให้ดู[รูปแบบไฟล์](#data)

## 3. เลือก algorithm

| Algorithm | Train นาน | ผลที่เราทดสอบ |
|---|---|---|
| **Maximum Entropy** :material-check-decagram:{ .pick title="แนะนำ" } | ไม่กี่วินาที | Testing 88%, ประโยคที่แต่งเอง 57–63% |
| Transfer Learning (BERT) | ประมาณ 17 นาที | Testing 89% แต่ประโยคที่แต่งเองแค่ 47% ตอบเป็น `fear` เกือบทุกประโยค |

ใช้ **Maximum Entropy** เร็วกว่ามาก และทายประโยคใหม่ได้ดีกว่า

!!! intel "{{ mac.intel }} · Xcode 26"
    Maximum Entropy train ได้เร็วบน {{ mac.intel }} เหมือนกัน อย่าเลือก Transfer Learning เพราะจะใช้เวลานานมาก

## 4. Train แล้วดูผล

กดปุ่ม **Train** (▶︎) มุมซ้ายบน แล้วดูผลในแท็บ **Evaluation**

| ตัวเลข | ได้ประมาณ | เชื่อได้แค่ไหน |
|---|---|---|
| Training / Validation | 99% | ไม่ค่อยได้ Validation แบ่งมาจากไฟล์ train เดียวกัน จึงคล้ายข้อมูลที่ model เรียนมา |
| **Testing** (`emotion6_test.csv`) | 88% | ดี เป็นประโยคที่ model ไม่เคยเห็น |
| **+ New Test** (`emotion6_mytest.csv`) | 57–63% | ใกล้การใช้งานจริงที่สุด เป็นประโยคที่เขียนแบบพูดทั่วไป |

ดูตาราง **Precision / Recall** ของแต่ละอารมณ์ด้วย `sadness` และ `joy` ทายได้ดี ส่วน `love` และ `surprise` อ่อนที่สุด เพราะมีข้อมูลน้อย และ `love` มักปนกับ `joy`

แท็บ **Preview** พิมพ์ประโยคทดสอบเองได้ทันที ลองพิมพ์ประโยคแบบที่ผู้ใช้ app จะพิมพ์จริง

## 5. Export และใช้ใน app

1. แท็บ **Output** › **Get** ตั้งชื่อไฟล์ว่า `EmotionClassifier.mlmodel`
2. ลากไปแทนไฟล์เดิมใน `Workshop3Starter/SensorParts/Models/` ของ starter project
3. Run แล้วเปิดแท็บ **Core ML** › **วันนี้รู้สึกอย่างไร** ลองพิมพ์ประโยค

ถ้าใช้ 6 อารมณ์เดิม ไม่ต้องแก้โค้ด ถ้า train อารมณ์อื่นเอง ให้เพิ่ม emoji และสีของอารมณ์นั้นใน `Mood` ของ `MoodView.swift` ดูวิธีเรียกใช้ model ในโค้ดที่ [Core ML](core-ml.md#text-classifier)

## ทำให้ model ดีขึ้น

- **Label ต้องถูก**: ถ้าข้อมูลติด label ผิด model ก็เรียนรู้สิ่งที่ผิด ระวัง dataset ที่ติด label อัตโนมัติจากคำในประโยค เช่น ประโยคที่มีคำว่า "not sad" ถูกติดเป็น `sadness` แบบนี้ Validation จะสูงเกือบ 100% แต่ใช้จริงทายผิดเกือบหมด
- **จำนวนใกล้เคียงกันทุก label**: ถ้า label หนึ่งมีข้อมูลมากกว่าที่เหลือมาก model จะเอนเอียงไปตอบ label นั้น
- **ข้อมูลแบบเดียวกับที่ผู้ใช้จะพิมพ์**: dataset นี้เกือบทั้งหมดเป็นประโยคแบบ "i feel …" ถ้าผู้ใช้ app พิมพ์แบบอื่น ให้เพิ่มประโยคแบบนั้นลงใน `emotion6_train.csv` แล้ว train ใหม่ เน้น label ที่อ่อน เช่น `love` และ `surprise`
- **ลดจำนวน label**: ถ้า app ไม่ต้องแยก `love` กับ `joy` ให้รวมเป็น label เดียว model จะแม่นขึ้น
- **ทดสอบกับประโยคใหม่เสมอ**: ตัวเลขจากข้อมูลที่ใช้ train บอกไม่ได้ว่าใช้จริงได้ดีแค่ไหน

!!! tip "ภาษาไทย"
    Model ที่ได้เข้าใจแค่ภาษาอังกฤษ เพราะข้อมูลเป็นภาษาอังกฤษทั้งหมด ถ้าต้องการภาษาไทย ต้องเตรียมข้อมูลภาษาไทยที่มี `text` และ `label` แล้ว train ใหม่ด้วยขั้นตอนเดียวกัน
